# Style Foundry workflow

On Windows, double-click **START-STYLE-FOUNDRY.cmd** after extracting the project. Node.js LTS must be installed. The launcher opens http://localhost:5173; use the same browser/profile as before to keep access to local projects.

## 1. Start with the client (2 minutes)

Create a project with a client and working title. In Overview, set the niche, format, deliverable count, and deadline. The checklist gives you the seven decisions to finish before editing. Open the Marcus Cole demo first to see an original dark/yellow/blue direction.

Already have a good system? Use the copy icon on a project card to **duplicate as template**. It keeps the palette, font trio, priorities, and board skeleton, clears the client answers/review history, and records reused assets. Edit the new client and vision immediately. Archive old projects with the archive icon; restore them from the Archived filter.

## 2. Send an intake that asks useful questions (5 minutes)

In Intake, use the default taste, references, dislikes, and animation sections. **Edit questionnaire** lets you add, remove, reorder, or save templates. Reference questions require a URL, a reason, and exactly what to take from it in the client form.

Download **Client form · HTML** and send the file to the client. They open it in a browser without an account, fill it in, and click **Download my answers**. They send that JSON file back; you use **Import answer file** in the same project. Nothing is submitted to a server. On phones that preview HTML instead of running it, ask the client to open it in their browser, or send the blank PDF and enter their replies yourself.

Blank and filled PDF buttons open a print window. Select **Save as PDF**. Allow pop-ups if your browser blocks the window. For DMs, paste the raw conversation into an intake note and enter the individual answers in the matching fields.

## 3. Extract the right things (5 minutes)

Add video URLs and titles in References, or pull the structured references from intake. Upload your own images/recordings, drop files, or paste screenshots while this workspace is focused. Record why the client likes each reference. Keep Take and Avoid lists to one idea per line.

For a still frame, open **Annotate frame**, choose note/box/arrow, enter a note, and click the frame. The annotation list lets you edit or delete it. Reference URLs open externally; the tool does not fetch or download their videos.

Build priorities, then visit Priorities. Drag rows or use the arrow buttons to rank them, and set Must / Should / Avoid. Choose animation quantity versus polish. Tight deadlines trigger a concrete trade-off recommendation.

## 4. Build from their world (4 minutes)

In Color Lab, upload a set, studio, logo, or thumbnail image. Click a pixel to sample the primary, or auto-extract a dominant palette locally. You can always choose colors manually with keyboard-accessible color inputs. Add a background rationale.

Use computed harmony suggestions for the secondary, adjust primary tone, and inspect the lower third, text card, chart, title, and transition. Check WCAG ratios before using accent colors for small text. Export your palette to your tools; use HEX handoff notes where ASE imports are unavailable.

## 5. Find the visual vocabulary (4 minutes)

Open Style library. Bulk-drop screenshots, or paste one. Active category, color-tag, pacing, and format filters become defaults for imports. Open a card to edit its name, tags, source, description, and what makes it work. Choose a target project and **Send to board**.

In Typography, set Primary / Secondary / Accent by name or pick a pairing starting point. **Scan font folder** reads user-selected local font metadata. Use Select font files as a fallback. Search, favorite, preview at different sizes/weights, and click a family to use as primary. Re-select the folder after reopening to reconnect local font bytes. Favorites and usage history persist.

## 6. Compose the direction (4 minutes)

Board offers Canvas and Pinterest views of the same objects. Add images, notes, swatches, type specimens, arrows, sections, and link cards. Drag objects; enable Pan to move the whole canvas; scroll or use +/- to zoom. The eight-zone template gives everything a place. Selected-object fields provide precise text, size, color, and layer control without dragging. Use read-only HTML for portable sharing, PNG for a visual, and the browser’s PDF print flow for a document.

## 7. Align before the edit (4 minutes)

In Brief, draft a vision from the inputs and make it sound like you. Review Client approval and Editor cheat sheet. Save a labeled version before sending a client-ready HTML brief or PDF. Version history shows which direction fields changed; choose an old version to preview/export it.

The HTML brief contains an Approve / Request Changes block. The client downloads feedback and sends it to you. Import it and confirm the recorded decision; approval updates project status and checklist. Feedback files are a practical handoff, not identity-verified signatures.

Export Markdown, JSON, PNG, or editing handoff notes as needed. Branding comes from Settings. User fonts remain references, never redistributed files.

## 8. Keep it close. Keep it safe.

Use Quick reference while editing: click HEX values and fonts to copy, glance at five priorities and the Avoid list. It is a compact in-app panel; browser security does not guarantee an OS-level always-on-top window.

Cmd/Ctrl+K opens navigation and project search. Escape closes dialogs. Switch themes in the sidebar or Settings. Data saves to the local database on edit. Use Settings & backup to export a full JSON backup before browser maintenance or moving devices. Restore replaces the current workspace only after validation and confirmation.

To work offline, first load the production application on localhost or HTTPS. The service worker retains the app shell, not a server or an account. Keep the same origin/profile to see the same local database.
